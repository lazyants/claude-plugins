# Hardening validation gates, schemas, and pipeline-trust primitives

A gate/schema/integrity check certifies only **what it can see**. Every recurring failure below is a way it silently passes a defect (false-GREEN / under-catch) or permanently blocks legitimate input (false-RED / over-catch). Front-load the relevant checklist; do not discover these one adversarial round at a time.

## Cross-cutting spine (applies to every gate here)

1. **Positive allowlist, fail closed — never a denylist.** Enumerating what to reject gets broken by a new shape every review round; a denylist that blocks `/ \ ..` still passes shell metacharacters. State the finite set of *accepted* shapes; everything else halts.
   **This applies to internal control flow, not just untrusted input — and that is where it gets missed, because nobody calls it a gate.** A branch over your OWN function's returned union is a gate: `if (r.kind === 'a' || r.kind === 'b') return unverifiable;` silently ADMITS every variant added later. Measured 2026-07-27 (`enduser-handbook` `verifyNonHeadingPlacement`): a new `{kind:'unwritable'}` outcome joined the accepted set with no code change and nothing red, while the sentence defining the accepted class — reused verbatim and pinned in FOUR files — still named the old set, so all four pins stayed green on a false claim. The fix is to enumerate the set that PROCEEDS, not the set that refuses — `if (!PROCEEDS.has(r.kind)) return unverifiable;` where `PROCEEDS` is the explicit, finite list of outcomes known to be safe. Note what this is NOT: flipping the same two names to `if (r.kind !== 'a' && r.kind !== 'b')` inverts the behaviour of `a` and `b` themselves, which is a different bug, not the fix. The point is which set is written down — a new variant must land outside the enumerated success set and halt until someone decides it belongs. **When you add a member to a returned union, grep every consumer for negative-list branches on it** — a compiler will not, a test will not unless one already exercises the new member through that consumer, and a doc pin cannot.
2. **Strictness bias — the only tolerable failure is a false-HALT, never a false-PASS.** For any ambiguous design choice pick the branch whose worst outcome is "safely refused" (remedy is idempotent) over "silently accepted a bad value." *When unsure, HALT.*
3. **Red-before-green is necessary but NOT sufficient — prove BOTH directions.** Watch the gate FAIL on the real defect, AND separately construct realistic *legitimate* content and prove it does NOT trip. A gate that over-catches hand-authored/LLM content is often worse than the under-catch it replaced. **Re-ask this of the PATH, not only of the gate you are adding** — a long adversarial loop bolts refusal after refusal onto one code path, each round honestly proving its own two directions, while nobody re-runs the ordinary end-to-end case; a suite made only of refusal tests cannot distinguish a correct refusal from a feature that now refuses everything. Measured 2026-07-31 (`enduser-handbook` asset walk): every nested-asset test on the branch was a refusal test after eight rounds of added refusals, and writing the missing ordinary-case one exposed that no test in twenty-two review rounds had ever driven the audit pass to a confident verdict at all.
4. **Front-load the whole checklist.** A single adversarial reviewer surfaces these one class per round, in the same order, even on a same-plugin precedent file. Paste the checklist into the plan up front instead of looping N times.
5. **Differential-test against a REAL oracle, then audit the harness.** Compare your reader against `ruby -ryaml` / `jsonschema` / `Psych` over hand-fixtures AND an adversarial (not ASCII-only) fuzz corpus. A green run over a blind corpus proves only the classes you fuzzed — run ≥1 adversarial reviewer as the backstop for the class you didn't think to fuzz. Also audit that the harness implements the spec (using `.trim()`/`\s` where the spec says ASCII-only *proves the wrong program*).
6. **Convergence is a SIMPLIFICATION, not another layer.** When a reviewer keeps returning same-CLASS collisions/false-passes, DELETE the clever machinery generating them (the sorter, the sentinel, the field projector) rather than adding context-awareness to it. A fix round that deletes code is converging; one that adds a guard is usually whack-a-mole.
7. **Schema is advisory unless `jsonschema.validate` actually runs at runtime — grep for it first.** If nothing validates the doc at runtime, the schema `pattern`/`enum` is documentation; the per-script runtime check is the load-bearing thing.
8. **Independent oracle — a gate that derives its expectation THROUGH the code under test is blind by construction.** If `expected` is computed by calling the same function whose output you are validating, `expected == actual` always holds and the gate exits 0 on every defect in that function — green forever, by design, not by bug. Ask of every gate: *where does its expectation come from, and could it disagree with the thing it checks?* Corollary: never cite such a gate as evidence a fix works. → [`references/gate-review-lenses.md`](references/gate-review-lenses.md)
9. **An empty-result sentinel that means "nothing to do" also means "nothing was detected".** A producer emitting `{no_new_candidates: true}` / an empty set / zero rows conflates *the work is already complete* with *my detector found nothing* — and consumers reliably assume the benign one, skipping the step that would have surfaced the failure. Make the two states distinguishable at the source, or have the consumer prove completeness independently. **The value-domain twin: an in-band sentinel meaning "absent" is itself a legal value the source can produce.** A gate whose allowlist admits `unknown`/`none`/`n/a` and whose absence marker *is* the string `unknown` records a source that emits that word as a successful result — the validator admits its own sentinel, and nothing downstream can separate the two. Represent absence STRUCTURALLY (`null`, or a separate field), never as a string drawn from the domain being validated; then every string, including the sentinel-looking ones, is just a value. → [`references/gate-review-lenses.md`](references/gate-review-lenses.md)
10. **Never let the value under test help DERIVE the reference it is tested against.** A containment gate ("X must resolve under root R") is silently destroyed if R is derived by searching for a root that *contains* X: the gate becomes vacuous at best, and at worst the search widens R until X fits — so the exact violation the gate exists to catch now PASSES (false-GREEN), and the wrong-but-wider R is then used for real output. Derive R from one independent anchor, test every other path against it, and on multiple candidate roots **HALT as ambiguous** rather than picking innermost/outermost — a tie-break here is a silent wrong answer. This is the derivation-side twin of lens 8 (independent oracle): 8 is about where an *expectation* comes from, this is about where a *reference frame* comes from. → [`references/gate-review-lenses.md`](references/gate-review-lenses.md)
11. **A deferred/found instance signals a CLASS.** State the invariant that bounds the whole class and open ONE tracking issue; do not patch instance-by-instance. Resolving error A by moving the same input's failure to error B is zero progress — enumerate the full failure set for the topology the fix targets.
12. **A green assertion proves ONE rung of a ladder, not the claim you read into it.** For prose/doc-contract gates (fixed-string, section-scoped, count- or line-order-based) the rungs are distinct and independent: *exists anywhere* → *in the right section* → *is NEW rather than a pre-existing attractor* → *in the right PLACE within that section* → *anchored to something unrenameable*. Passing rung N says nothing about N+1. Two orthogonal checks belong with it: **satisfiability** — individually-reasonable assertions can be JOINTLY impossible (a required sentence whose own identifier a negative pin forbids in the same section), so review PAIRS, never single assertions; and **witness completeness** — a requirement with N normative outcomes needs N witnesses, or the implementer writes the setup plus one and omits the rest with everything green. The ladder never terminates in a fixed-string world, so bound the threat model in the artifact (careless implementation and drift, *not* a hostile author) and file the structure-aware parser. → [`references/gate-review-lenses.md`](references/gate-review-lenses.md) §7
13. **A destructive filesystem gate — "clean the managed dir, then rebuild" — is a symlink DATA-LOSS / out-of-root-write surface.** Every dotfile you PRESERVE across the clean (an ownership marker, its write-temp, snapshot dirs) is a symlink-survival vector, and `is_file()`/`is_dir()`/`mkdir(exist_ok=True)`/`Path.resolve()` ALL follow symlinks — so a planted symlink silently clobbers an out-of-root target on WRITE and bypasses an ownership gate (a green suite hides every vector). (Delete-THROUGH is narrower: `rmtree`/`rm -rf` of a symlink removes only the link — deleting INTO the target needs the CONTAINER dir to be the symlink, or an explicit follow-links walk.) Require REAL regular files (`is_symlink()` BEFORE `is_file()`), write atomically via `mkstemp`(`O_EXCL`, no-follow)+`os.replace`, normalize paths NO-FOLLOW (`os.path.abspath` + reject `..`, NEVER `.resolve()` upstream of the guards), and stop the symlink walk at the trusted install root — with a false-RED tail: don't over-reject real OS symlinks (`/var`,`/tmp`) on an out-of-root path. → [`references/gate-review-lenses.md`](references/gate-review-lenses.md) §9

14. **A halt's REMEDY is a separate correctness claim from its diagnosis — every word can be true and the instruction still not converge.** A gate that refuses and tells the operator what to change is only as good as the *next run* after they do it. Verify by FOLLOWING the remedy literally in a fixture and asserting the next run succeeds; a remedy that leads to a different halt is a defect even when every sentence in it is measurably true. The recurring cause is a **scope mismatch between the field the remedy names and the scope that field actually has**: check whether each named value is per-entity, per-group, or global, because the validator enforcing that scope is usually a *different* function and nothing at the halt site reveals it. Measured 2026-07-27 (`enduser-handbook`): a halt said "give this chapter a plain `group_title`"; `group_title` is group-scoped, so the compliant one-entry edit hit the conflicting-value gate on the next run and the chapter still was not wired — and this halt had itself been written to fix an earlier non-convergent remedy, so the defect simply moved one gate downstream. Two corollaries: state the remedy as the edit that actually converges (here, "on EVERY entry of the group"), and prove idempotence — same input twice, same outcome, nothing written — so a stable refusal is distinguishable from a lockout. → [`references/gate-review-lenses.md`](references/gate-review-lenses.md)

15. **A bounded parser is sound for a SEARCH and unsound for a CENSUS — reusing one for a completeness check turns each of its documented limits into a false PASS.** A scanner written to *find* an occurrence may legitimately decline hard cases; its original caller just looks elsewhere. A gate that must enumerate *every* occurrence inherits each decline as a silent miss, and a miss in a completeness check is a false GREEN — the artifact is certified as fully covered precisely because the checker could not see the uncovered part. The tell is a reuse comment like "no support for X, out of scope" in the parser you are about to call: true for its author, fatal for you. Measured 2026-07-28 (`enduser-handbook`, image-completeness gate over Markdown): four consecutive review rounds each found a *new* live construct the reused scanner dropped — nested-bracket labels, reference/collapsed/shortcut forms, fences opened at an undecidable column, tabs, raw HTML tags, HTML character references in destinations, query/fragment suffixes, and an unmatched code-span opener that made the stripper blank a live region to EOF. Adding a case per round is unbounded; the fix that ended it in one step is **completeness-or-halt**: recognise an explicitly named subset, and **halt naming the construct** on anything the parser cannot prove it accounted for. Two corollaries. Check that the recognised subset still covers the system's own generated output, or the gate is unusable on day one (here: the shipped chapter template and both publish adapters emit only the recognised form — verified by scanning them for every halt trigger, zero hits). And distinguish a trigger that is *missed* from one that is *erased*: a construct wrongly classified inert is worse than an unparsed one, because the classification is the very thing the gate trusts to decide what is live.

16. **When the artifact under audit is your own system's OUTPUT, stop parsing it and compare it against its GENERATOR — then close the loop back to the generator's INPUT, because the generator normalizes.** Completeness-or-halt (15) bounds the damage of a bounded parser; this removes the parser. If the document was written by an adapter/template/serializer you ship, the question is not "what does this arbitrary input mean" but "is this the string my generator would have produced" — so enumerate the generator's real inputs (the directory listing, the row set), call **the generator's own function** per input, and require byte-exact equality against that candidate set. Every alias class dies at once and for a structural reason rather than by a longer denylist: the generator emits none of those spellings. Two hard-won caveats, both of which cost a full extra review round after the naive version shipped. **(a) The alias moves to the generator's INPUT.** A candidate built from a filename containing the special character *is* the special spelling — a file literally named `a&#46;png` yields a candidate the renderer resolves to `a.png` — so the generator side needs its own gate: each candidate must round-trip back to the input that produced it, and no two inputs may collide *after* the consuming layer's normalization (compare rendered/resolved forms, never literals). **(b) Comparing the candidate to ITSELF is vacuous**, and looks exactly like a real check: the generator already normalized it, so a file named `sub\stale.png` yields `sub/stale.png`, whose self-comparison trivially succeeds while no such file exists. Also budget for the generator's *sanctioned history* — a spelling it no longer emits but deliberately never rewrites — or the gate false-halts on legitimately retained output, which is a permanent refusal on ordinary content. Measured 2026-07-28 (`enduser-handbook`): seven review rounds of destination-alias findings collapsed to one equality check, and rounds 25-26 then produced (a) and (b) in turn.

17. **A guard that re-checks a resource across a window proves SAMENESS only if it reads an IDENTITY — a type, shape, or name check proves the CLASS, not the object.** Measured 2026-07-31 (`enduser-handbook` asset walk): a subdirectory was `lstat`ed before and after its own listing and required to still BE a directory, to catch one swapped for a symlink mid-walk. Replacing it with a *different ordinary directory* passed both observations — two `lstat`s that both answer "directory" are not two `lstat`s that answer "the same directory" — so bytes from a tree the chapter did not own were hashed as its asset with an empty hazard list, through the guard written to stop exactly that. The property being asserted was identity; the check read a type. Compare an identity token: `dev`+`ino` for a filesystem object, ETag/generation for an HTTP resource, a version column for a row, start-time for a pid (pids are reused). Ask of every re-check: *what would a substituted object look like to this comparison?* Four corollaries, each of which cost its own finding:
    - **Fail closed when the identity cannot be READ.** A caller whose stat lacks those fields otherwise compares `undefined` to `undefined` — which is EQUAL — so the guard reports success precisely because it learned nothing. That branch killed no test until it was given one of its own.
    - **State the reach where the check is written.** A re-check bounds the window between its OWN observations and nothing else. Where the identity cannot be bound at all, say so instead of implying the window is closed: a `Dirent` carries a name and a type and no inode, so the name a parent listing saw can never be tied to the object descended into without an `openat`/`d_ino`-style API — a seam change, not a logic change.
    - **A re-check by NAME detects a race; it does not close the window.** Re-reading a path/URL/key and comparing identities proves the object was the same *at each observation instant*. The operation in between resolved that name independently, so it is not bound to the object that was checked: a substitution installed and reverted between two adjacent observations is invisible, and one that is caught is caught only because it happened to persist. Closing the window needs a HANDLE the later operation acts *through* — an fd from `openat`/`fdopendir`, `If-Match` on the request that writes, a row lock or a compare-and-swap on the version column. Where the seam offers no handle, write "best-effort detection" and mean it; a comment claiming the window is shut is the overclaim this lens exists to catch, one level up.
    - **When detection is all you have, two observations are rarely the right number.** Check before the read, *between the read and any use of its result*, and after the result is consumed. The middle one is the cheapest to omit and the most valuable: it is the difference between refusing before a byte of the replacement is used and reporting the substitution afterwards.

18. **An allowlist of *legitimate matches* needs a match SPAN and an occurrence COUNT, or it is a false-GREEN generator.** When a gate sweeps prose for claims a release invalidated, some hits are legitimate and must be exempted — but keying an entry on `(path, token)` exempts **every** occurrence of that token in that file. Measured 2026-07-28 (`literary-translator` doc-contract sweep): one file carried the identical invalidated formula three times — legitimate history, a **stale present-tense contract**, legitimate history again — so a `(path, token)` entry silently absolved the one occurrence the gate existed to catch, and two implementers reading "allowlist by path and exact text" would build materially different gates, one of them green on a live defect. Each entry keys on the **full whitespace-normalized claim sentence**, records the **expected occurrence count**, and the gate fails when that count moves in *either* direction — a new occurrence, or a vanished one meaning the entry is now dead and should be deleted. Prove it with a duplicate-match mutation (insert a second copy of an allowlisted sentence) as part of the gate's own red-first proof. Two companions: the exemption criterion is **reviewed-legitimate-match**, not "historical" — a present-tense claim can be simply true — and a whole-file exclusion (a CHANGELOG, whose claims are version-scoped by construction) belongs in the gate as a stated *rule*, never as an unexplained skip.

19. **Verifying a value and then re-reading its source checks a different read.** An integrity check over caller-supplied state certifies the values it READ; if the consumer reads them off the original object again, nothing forces the two reads to agree. Plain-object tests do not exclude accessors (`typeof x === 'object'` is true of an all-getter object), so a getter can answer the check with the authenticated value and the consumer with another. Materialize once — where the check canonicalizes, parse the canonical TEXT back and pass that object downstream — and treat it as a property of the SEAM rather than of the one field a reviewer names. Build the RESULT from the materialization too: a value returned to the caller is an output like any other, so "this read happens after every decision" does not make it benign. Then widen past that object: enumerate every INPUT the same caller supplies — a profile, a config, an options bag — because a branch deciding on one of THOSE is unauthenticated in the same way while reading nothing from the state you just hardened; and when the caller owns every input, no reflective test can help (a `Proxy` traps them all), so bound the guarantee instead of adding a gate. → [`references/pipeline-trust.md`](references/pipeline-trust.md) §4
