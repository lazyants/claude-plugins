Publishing and maintenance mechanics for THIS claude-plugins marketplace repo. Two cross-cutting rules apply everywhere below:

- **Verify from `origin/main`, never from a tool's success output.** A merge command's changed-file list, a commit message's "N surfaces synced" claim, and a green local suite are all NOT proof. Re-grep the actual value on `origin/main`.
- **Worktree teardown / branch-revival / parallel-session-race mechanics live in the `git-worktree-pr-mechanics` skill** — this skill points there rather than duplicating them.

Read the reference file that matches the task:

- **`references/version-and-surface-sync.md`** — read when bumping a plugin's version, adding a new plugin, or adding/renaming an `ai-cli-optout` vendor. Covers the four synced surfaces (plugin.json, marketplace.json, CHANGELOG, README row/header/anchor/prose), the README anchor-slug gotcha, the repo-level `metadata.version` +0.1.0 rule for a NEW plugin, the vendor-add README sweep, re-deriving a measured figure inside a CHANGELOG entry/PR body before pinning it, and a correctly-unbumped PR landing right after a sibling's release cut.
- **`references/merge-and-review-bot.md`** — read when merging a PR, verifying a squash landed the right content, predicting or resolving a parallel-PR conflict on the shared registration surfaces (including one hand-resolved hunk silently reverting a SIBLING plugin's row), a same-plugin version-number collision across concurrent releases, dealing with a stacked PR or a stale-base branch, auto-closing multiple issues, auditing what's genuinely unmerged, or handling the `lazy-ants-reviewer` bot.
- **`references/skill-parameterization.md`** — read when designing a skill whose behavior must vary per project (a new configurable plugin skill, or a "configurable" skill proposed anywhere). Covers why no frontmatter/`args`/env mechanism exists, the surveyed frontmatter fields, and the read-a-known-per-project-file pattern that actually works.
- **`references/publishing-and-cli.md`** — read when running any `claude plugin …` CLI op, reading or reporting an installed plugin's VERSION (never from a `plugins/cache/` path glob), fixing a "corrupted installLocation" rejection, refreshing the installed copy after merge, or scrubbing author-local paths / non-shipped-file directives before publishing a plugin generalized from a private project.
